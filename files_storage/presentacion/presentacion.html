1. Petición del Usuario

El usuario escribe un mensaje en la interfaz. JavaScript empaqueta el prompt y lo envía a Django mediante fetch('/api/chat/') en formato JSON.

2. Delegación y Ejecución

Django inyecta la API Key de Anthropic, carga el system prompt y la memoria. Si Claude decide invocar una herramienta (escribir o leer un archivo), Django ejecuta la acción localmente y le devuelve el resultado.

Paso 1 · Framework Django

Estructura del Proyecto en Django

Organización limpia separando configuración (core/) de lógica de aplicación (app/)

iaDesk/
├── core/                  # Configuración central Django
│   ├── settings.py        # Variables, apps, middleware
│   ├── urls.py            # Router raíz de URLs
│   └── wsgi.py            # Punto de entrada Web Server
├── app/                   # Módulo principal de la aplicación
│   ├── views.py           # Controladores de IA y Archivos
│   ├── urls.py            # Rutas API de la app
│   ├── templates/         # index.html
│   └── static/            # CSS, JS, imágenes
├── files_storage/         # Directorio de trabajo local
└── manage.py              # CLI de Django
⚙️

Conceptos Clave de Django

  • Modularidad: La lógica de negocio y endpoints viven dentro de app/views.py.
  • Desacoplamiento: Las plantillas HTML y estáticos están centralizados sin mezclar código backend con presentación.
  • Almacenamiento Aislado: STORAGE_DIR se define en settings.py apuntando a files_storage/ para fácil portabilidad.
Paso 2 · Django Settings

Configuración Crítica en settings.py

Ajustes de middleware, almacenamiento local, y seguridad de cabeceras

# core/settings.py
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# Carpeta física de almacenamiento
STORAGE_DIR = BASE_DIR / 'files_storage'

INSTALLED_APPS = [
    # Apps internas de Django...
    'app',
]

# Permitir iframes y visores del mismo origen
X_FRAME_OPTIONS = 'SAMEORIGIN'

TEMPLATES = [{
    'DIRS': [BASE_DIR / 'app' / 'templates'],
    'APP_DIRS': True,
}]
🛡️

Puntos Clave de Seguridad

  • STORAGE_DIR Seguro: Centraliza la ruta absoluta para evitar accesos indebidos fuera de la carpeta designada.
  • X_FRAME_OPTIONS = 'SAMEORIGIN': Permite que vistas previas embebidas funcionen de manera segura dentro de la aplicación.
  • ALLOWED_HOSTS: Define qué dominios o IPs tienen autorización para consultar el servidor Django.
Paso 3 · URLs & Routing

Enrutamiento de Peticiones (urls.py)

Conectando las rutas del navegador y los endpoints REST con las vistas de Django

# app/urls.py
from django.urls import path
from . import views

urlpatterns = [
    # 1. Vista principal HTML
    path('', views.index, name='index'),

    # 2. Endpoint del Agente Inteligente
    path('api/chat/', views.ai_chat, name='ai_chat'),

    # 3. CRUD de Archivos Locales
    path('api/files/', views.file_crud, name='file_crud'),
    path('api/files/raw/', views.file_raw, name='file_raw'),
    path('api/folders/', views.folder_crud, name='folder_crud'),
]
🔀

Mapeo de Funcionalidades

  • views.index: Renderiza la plantilla principal index.html.
  • views.ai_chat: Recibe los mensajes del usuario, administra la memoria y se conecta con Anthropic.
  • views.file_crud: Permite listar, leer, crear y guardar archivos en tiempo real desde la interfaz o por orden de la IA.
Paso 4 · Seguridad & API Keys

Manejo Seguro de Credenciales y .env

Buenas prácticas para nunca exponer ni quemar API Keys en el código fuente

❌

Mala Práctica: Hardcoding

# ¡PELIGRO! NUNCA HACER ESTO:
api_key = "sk-ant-api03-xxxx-secret-key"
client = anthropic.Anthropic(api_key=api_key)

Si subes este archivo a GitHub, bots automatizados robarán tu clave en segundos, consumiendo saldo o agotando cuotas.

✅

Buena Práctica: Variables de Entorno

# .env (Agregado a .gitignore)
ANTHROPIC_API_KEY=sk-ant-api03-xxxx...

# En Python:
import os
api_key = os.environ.get('ANTHROPIC_API_KEY')
client = anthropic.Anthropic(api_key=api_key)

El archivo .env permanece únicamente en tu máquina local o contenedor Docker y se documenta mediante un .env.example limpio.

🔒 Regla de Oro: El archivo .env NUNCA debe commitearse. Solo se comparte .env.example con variables vacías para guiar la instalación.
Paso 5 · SDK Anthropic

Conectando Django con Anthropic Claude

Inicialización del cliente y configuración de parámetros en views.py

import os
import anthropic

def ai_chat(request):
    api_key = os.environ.get("ANTHROPIC_API_KEY")
    if not api_key:
        return JsonResponse({"error": "Falta ANTHROPIC_API_KEY"}, status=500)

    # 1. Instanciar cliente oficial de Anthropic
    client = anthropic.Anthropic(api_key=api_key)

    # 2. Cargar System Prompt desde claude.md
    system_prompt = Path("claude.md").read_text(encoding="utf-8")

    # 3. Invocar al modelo
    response = client.messages.create(
        model="claude-3-7-sonnet-20250219",
        max_tokens=4096,
        system=system_prompt,
        messages=conversation_history,
        tools=available_tools
    )
🧩

Parámetros Esenciales

  • model: El modelo asignado para razonar y decidir herramientas (ej: Claude 3.7 Sonnet).
  • system: Instrucciones globales de rol y conducta inyectadas desde claude.md.
  • messages: Array con el historial de mensajes estructurados [{"role": "user", ...}, ...].
  • tools: Especificación JSON de herramientas disponibles para el agente.
Paso 6 · Tool Calling

Bucle de Ejecución de Herramientas

Cómo Claude decide ejecutar código o crear archivos y Django lo concreta

# Bucle de Tool Calling en views.py
while response.stop_reason == "tool_use":
    tool_results = []
    for block in response.content:
        if block.type == "tool_use":
            # 1. Django ejecuta la acción local
            result = execute_local_tool(block.name, block.input)
            
            # 2. Registra el resultado
            tool_results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": str(result)
            })

    # 3. Re-enviar respuesta de la herramienta a Claude
    messages.append({"role": "assistant", "content": response.content})
    messages.append({"role": "user", "content": tool_results})
    response = client.messages.create(...)
🛠️

Herramientas Nativas Disponibles

  • read_file: Permite a Claude inspeccionar el contenido de cualquier archivo en files_storage/.
  • write_file: Permite a Claude escribir o sobrescribir archivos reales en disco.
  • append_memory: Agrega nuevas decisiones o acuerdos en MEMORY.md.
  • update_memory: Reorganiza las secciones activas de la memoria permanente.
Paso 7 · Memoria Continua

Memoria Continua y Enrutador Semántico

Estrategia para retener contexto sin saturar la ventana de tokens de la API

🗂️

1. INDEX.md

Router Semántico de Archivos:

Catálogo liviano con temas, resumen y cuándo consultar cada documento. Claude lo lee primero para saber qué archivo abrir sin cargar todo a ciegas.

🧠

2. MEMORY.md

Memoria Persistente de Negocio:

Almacena decisiones técnicas, perfil del usuario, lineamientos y tareas activas. Permanece intacta entre reinicios del servidor.

💬

3. Ventana Deslizante

Historial de Conversación:

Mantiene los últimos N mensajes en CHAT_HISTORY.json para fluidez conversacional inmediata, evitando desbordar el límite de tokens.

💡 Ahorro de Tokens: Al consultar primero el índice semántico, Claude solo lee los archivos estrictamente necesarios para la consulta del usuario.
